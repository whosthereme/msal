# Data

The paper uses frozen features of the public SmolVLA checkpoint and three task families. The two placement
families were recorded for this work and are attached to the release
[`data-v1`](https://github.com/whosthereme/msal/releases/tag/data-v1) (5.5 GB in ten files, each below 1 GB).
They hold features and actions only: no images, no model weights.

| Dataset | What it is | Files in `data-v1` |
|---|---|---|
| Placement family (development) | 41 placement targets of one pick-and-place skill in a LIBERO-style scene, 24 scripted demonstrations each (16 / 4 / 4 by split); 26,680 rows of frozen SmolVLA features with 16-step action chunks | `v5_language_conditioned_state_action_fields.npz.part00` to `.part03` (3.1 GB after joining) |
| Cluttered placement family (closed loop) | 40 targets, a scanned bowl or ramekin among 5 to 11 scanned objects; 20 scripted demonstrations per target (14 / 3 / 3), 38,190 rows of frozen features with action chunks, and a record of every episode | `cluttered_shards_1000-1009.tar` to `cluttered_shards_1030-1039.tar` (2.4 GB) |
| Scenes of the cluttered family | Scene definitions of the rollouts and demonstrations, the list of scanned objects and the size catalog | `cluttered_scenes.tar.gz` (0.3 MB) |
| LIBERO, 40 tasks | Public benchmark with human demonstrations | https://github.com/Lifelong-Robot-Learning/LIBERO |
| SmolVLA checkpoint | Public pretrained model, never updated here | https://huggingface.co/lerobot/smolvla_base |

`SHA256SUMS.txt` in the release lists the digest of every file and of the joined development file.

## Development family

Join the four parts and check the digest:

```
cat v5_language_conditioned_state_action_fields.npz.part0? > v5_language_conditioned_state_action_fields.npz
sha256sum v5_language_conditioned_state_action_fields.npz
# 99efd134456987b75fc94df2088cb90f60b0057d337cb46b93d642cebe539ff0
```

The loaders (`code/method/msal_exp/data_lang.py`, `code/base/sal_v2_identifiable/lib/`) expect the file at
`runs/20260813_g33_v5_language_substrate_v1/data/` next to the `sal_v2_identifiable` package. Arrays, one row per
recorded step:

| Array | Shape | Meaning |
|---|---|---|
| `frozen_extractor_features` | 26680 x 31680, float16 | The feature used in the paper: SmolVLA vision tokens of the scene and wrist images, average-pooled to 4 x 4, and the projected robot state; it does not see the instruction |
| `state_features` | 26680 x 31680, float16 | A second feature block that sees the instruction (pooled joint prefix); not used in the paper |
| `action_chunks`, `action_valid_masks` | 26680 x 16 x 7, 26680 x 16 | The next 16 actions and their validity |
| `task_ids`, `direction_indices`, `radius_indices` | 26680 | Target position: task, direction (16) and ring (4) |
| `episode_indices`, `step_indices` | 26680 | Demonstration and step within it |
| `split_codes` | 26680 | 0 TRAIN, 1 SELECTION, 2 ROBUSTNESS (split by episode) |
| `task_split_codes`, `feature_available` | 26680 | Constant here (all source tasks, all rows available) |

## Cluttered family

Each archive unpacks to `shards/task{1000..1039}.npz` and `.json`; `code/libcoord/lc_heads.py` reads them from
`shards/` next to the scripts. Arrays per target: `state_features` (rows x 31680, float16, the same feature as
above), `action_chunks`, `action_valid_masks`, `task_ids`, `episode_indices`, `step_indices`, `split_codes`. The
`.json` beside each shard records every attempted episode: vessel, start position, clutter objects, success and
length. `shards/SHA256SUMS` lists the digests of the forty shards.

`cluttered_scenes.tar.gz` holds the scene files of the rollouts (`bddl/`) and of the demonstrations
(`bddl_demo/`), the selection of scanned objects (`gso_selection.json`) and their size catalog
(`assets/libero_gso/catalog.json`). The object meshes are not redistributed: they come from Google Scanned
Objects (Google Research, CC BY 4.0) in the MuJoCo conversion at
https://github.com/kevinzakka/mujoco_scanned_objects, and `code/libcoord/lc_assets.py` converts the selected
objects to LIBERO's object layout:

```
python lc_assets.py <mujoco_scanned_objects/models> gso_selection.json assets/libero_gso
```

The scenes themselves are generated by `code/libcoord/lc_scene.py` and `lc_tasks.py`.

## Not included

Model checkpoints are not part of this release. Everything derived from these data that the paper reports
(per-fold errors, per-episode outcomes, analysis outputs) is in `results/`.
